# 手机与 TV 账号同步使用说明

适用版本：**手机 / TV App 0.12.7**，配套 **Go + Gin 服务 0.2.0**。

同一账号可以同步观看历史、看到的集数和播放进度。视频、投屏、连播和缓存仍由原来的播放器处理，不经过账号服务器。

## 一、先准备服务器

1. 按 [服务器部署说明](../server/login/README.md) 部署 `hongguo-login 0.2.0`。已有服务器进程管理方式可以继续使用，不要求 Docker。
2. 在服务器创建普通账号。没有公开注册页面，手机和电视使用这个普通账号，不填写服务器 SSH 账号。
3. 配置有效证书的 HTTPS 反向代理，指向服务监听地址（默认 `127.0.0.1:8787`）。
4. 确认外部设备能访问 `https://你的域名/healthz`。这只说明服务可达，还需要完成下方的登录与同步检查。

### 已部署 0.1.0 的用户

**先升级服务器，再使用 App 同步。** 0.1.0 只有登录接口，没有观看记录接口；可能出现登录成功，但同步提示 HTTP 404。

升级前停服务，备份旧程序、配置及整个数据目录；替换 0.2.0 可执行文件后，继续使用原来的 `DB_PATH`，保留原账号和数据。详细命令见服务器说明的“从 0.1.0 升级”。

如果沿用了旧版 Nginx 示例配置，还要把该服务代理中的 `client_max_body_size` 从 **`8k` 改为 `1m`**，检查配置通过后重载 Nginx。只换 Go 程序但保留 8k 限制，较大的同步请求可能被代理拦截并返回 HTTP 413。

## 二、手机和电视登录同一账号

两台设备分别操作：

1. 安装对应的手机或 TV **0.12.7** 安装包。
2. 打开 **关于 → 账号与同步**。也可以从 **我的追剧 → 账号与同步** 进入。
3. 填写相同的服务器根地址，例如：
   - `https://sync.example.com`
   - 使用其他 HTTPS 端口时：`https://sync.example.com:9443`
4. 填写服务器上已创建的账号和密码，点击 **登录并同步**。
5. 等待同步结束，核对页面显示的当前账号、服务器、最近同步时间和待同步数量。

地址只填写根地址，不加 `/v1`、`/v1/auth/login`、其他接口路径、查询参数或账号密码。手机和电视都需要信任服务器证书；App 不跳过证书校验。登录成功后，设备会保存服务器地址和登录状态。

TV 可以用遥控器上下键依次进入服务器地址、账号、密码和登录按钮；左右键可在输入框中移动光标。输入由电视系统键盘完成。

用户名规则为 3–32 位英文字母、数字、点、下划线或短横线，服务会统一为小写。密码由服务器创建时设置；忘记密码时由管理员重置，重置后各设备需要重新登录。

## 三、把以前的本机记录带到账号里

登录不会自动把游客历史上传，也不会混入其他账号的记录。原来的本机记录仍然保留。

如需迁移：

1. 先等待当前账号首次同步完成。
2. 在 **关于 → 账号与同步** 点击 **导入本机游客记录**。
3. 阅读确认提示，再点击 **确认导入**；点击 **取消** 则保持原样。
4. 查看导入和跳过数量，再等待同步完成。另一台设备点击 **立即同步** 后查看结果。

导入只补充账号中没有的剧，保留云端已有进度；本机原游客记录不删除。已有记录或无效旧记录会被跳过。每台设备的游客历史独立，如果手机和电视原来都有记录，可以在两端分别确认导入；建议一次完成一台，确认同步结束后再操作另一台。

## 四、换设备继续看

1. 在设备 A 看完或暂停后返回 App，让观看进度保存并同步。着急换设备时，到 **账号与同步 → 立即同步**。
2. 在设备 B 登录相同服务器、相同账号，等待自动同步，或点击 **立即同步**。
3. 打开 **我的追剧 → 观看历史**，卡片会显示看到第几集和播放位置。
4. 点开对应短剧，查看上次观看信息，点击 **继续播放**；也可以播放已经选中的对应集。

播放器按真实剧目和分集读取进度，不把“集数更大”当成“更新的记录”。已经到片尾的集，再次打开可能从头播放，这是原播放器的片尾恢复规则。分季仍可手动切换，**自动连播只在当前季内继续，不自动跳到下一季**。

两台设备同时播放同一部剧时可能出现进度冲突。页面若提示其他设备已更新，会保留云端记录；退出播放器后重新打开，或停止投屏再重新连接，即可继续记录，避免旧播放会话不断覆盖新的进度。

## 五、断网、退出与重试

- **同步服务临时不可达：** 已产生的观看进度继续保存在本机。App 运行时会重试；重新打开或回到 App 时也会尝试同步。页面会显示待同步数量和最近错误，可以点击 **重试同步**。
- **同步与视频播放分开：** 账号服务器不可达不会额外阻止原播放器；没有缓存的视频仍需要片源网络。
- **登录过期或密码被重置：** 按页面提示重新登录。本机账号记录保留，登录后继续同步。
- **退出账号：** 先确认待同步数量为 0 更稳妥。点击 **退出账号 → 确认退出** 后，页面改为显示游客历史；该账号在本机的独立记录和服务器历史仍保留。
- **切换账号或服务器：** 先退出，再填写新的地址和账号登录。不同账号分别保存观看记录，不会自动合并。

待同步记录尚未上传时，请保留 App 数据；卸载或清除应用数据可能丢失这些本机记录。

## 六、哪些内容不会同步

| 内容 | 处理方式 |
| --- | --- |
| 观看历史、当前分集、播放进度 | 同一账号同步 |
| 收藏 / 我的追剧收藏列表 | 每台设备各自保留 |
| 搜索历史 | 每台设备各自保留 |
| 手动下载的视频和下载任务 | 保留在原设备 |
| 视频缓存、取源地址、当前投屏连接 | 不上传账号服务器 |
| 清晰度、倍速、播放设置 | 沿用每台设备现有设置 |

**原来的投屏、同季连播、投屏后 5 集预缓存和已看缓存自动清理保留。** 缓存仍在手机 / 播放设备上，不在服务器上；实际预缓存数量仍受容量、片源和下载速度影响。另一台设备同步到观看进度后，需要自行取源播放，不会下载前一台设备的缓存文件。

## 七、首次检查建议

首次接入可以先用一集短视频做检查：

1. 手机和 TV 确认地址、账号完全一致。
2. 手机播放约半分钟，返回后点击立即同步。
3. TV 点击立即同步，在观看历史确认同一集和大致相同的时间，再继续播放。
4. TV 暂停并同步，回手机核对新的进度。
5. 最后再试原有投屏和连播；账号同步状态不代表电视已经出画，投屏问题仍以投屏诊断为准。

常见提示：

- **HTTP 404：** 核对服务器是否已升级为 0.2.0，以及代理是否把根地址下的 `/v1/history` 路径转发到同一个服务。
- **HTTP 413：** 核对 Nginx 等代理的请求大小限制，当前示例为 `1m`。
- **登录已过期 / 401：** 重新登录，或联系管理员核对账号是否被停用、密码是否被重置。
- **429 / 请求较频繁：** 等待后重试，不要连续点击登录或同步。
- **证书或连接错误：** 检查 HTTPS 证书、域名、端口和手机 / TV 到服务器的网络。
